# ShopQR Backend

ShopQR Fastify API for Node.js, with PostgreSQL and optional Supabase/storage
integrations. The API, routes, security helpers, database setup and environment
configuration are TypeScript source under `src/`.

## Structure

```text
backend/
  src/
    routes/                 HTTP method/path registration and controller wiring
    controllers/            Request handlers and API response mapping
    admin/                  Platform-admin access policy and route adapters
    security/               Authentication, authorization and request protections
    plugins/                Database and Supabase setup
    config/                 Environment configuration
    database/               Migration runner
  build/                    Generated TypeScript output; do not edit by hand
  migrations/               Numbered SQL migrations and migration instructions
  uploads/                  Local uploaded files
  scripts/
    data/                   Manual menu/category/image data tools
    setup/                  Initial local database and environment setup
    README.md               Script purposes and commands
  .env                      Local runtime configuration
  .env.example              Configuration template
  package.json              Commands and dependencies
  package-lock.json         Locked dependency versions
```

`src/` is the only application source. `build/` is generated by `npm run build`.
Uploads and environment files are runtime data and must not be committed.
Starting the API does not run data tools or apply database migrations.

## Run

From this folder, run `npm run dev` during development. For a production-style
start, run `npm run build` followed by `npm start`; Fastify listens on port 4000.
`/health` checks the process and `/ready` checks the database connection. To start the local database and API together, use
`powershell -ExecutionPolicy Bypass -File ../start-local.ps1 -Service backend`.
See the [project README](../README.md) for all local services.

Manual data and setup commands are described in [scripts/README.md](scripts/README.md).
They are separate from startup.

## Application modules

`src/server.ts` starts the Fastify server and `src/app.ts` registers plugins and
route groups. `src/routes/` maps HTTP methods and paths to controller handlers;
`src/controllers/` handles requests and builds responses. Keep each domain in
its own pair of modules. `src/security/` holds access checks and
`src/admin/authorization.ts` holds platform-admin access policy. Add database
schema changes under `migrations/`.

Only commands that point to scripts present in this checkout are exposed in
`package.json`. Administrative maintenance operations that do not have a
maintained TypeScript implementation are not exposed as npm commands.

New backend image uploads are stored in R2 using server-only credentials.
`R2_BUCKET` is supported, with `R2_BUCKET_NAME` retained as a compatibility
alias. Never expose R2 secrets to browser variables such as `VITE_*`. The
`uploads/` directory only serves legacy local images; keep them until their URLs
have been migrated, then it can be removed from the server and backups.

`npm run db:migrate` runs the built `build/database/migrate.js`. Read
[migrations/README.md](migrations/README.md) before using it.
Before deploying a backend version that grants the three-month Pro trial to new
restaurant signups, build the backend and apply pending migrations with
`npm run db:migrate`, then restart the API. Migration `0040` adds a separate,
one-per-restaurant trial record; it does not rewrite existing restaurants or
Pro request history.
